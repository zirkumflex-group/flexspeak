# Flexspeak audio processing research

Date: **2026-11-01**. Research only; no implementation, builds, benchmarks or hardware capture performed. “Krips” is interpreted as **Krisp**.

Implementation follow-up: WebRTC suppression, gain and experimental AEC were subsequently added on `changes-next-2`; see [current controls and validation](controls-and-settings.md#audio-processing-options). The findings and proposals below record the research stage.

**Recommendation**

Reuse the already pinned WebRTC Audio Processing Module (APM) for a first **macOS/Windows microphone noise-suppression option**, with optional automatic gain control (AGC). This is the smallest integration supported by the inspected dependencies; it is not a claim that WebRTC sounds better than Krisp. Keep acoustic echo cancellation (AEC) off until playback-reference and timing handling are implemented and validated. The existing Rust binding exposes all three effects, but does not connect them to Flexspeak’s CPAL/Opus path automatically. [Pinned API][apm-rs], [current audio path][audio].

Treat embedded Krisp as a separate commercial evaluation, and its desktop app as a possible user-installed workaround. RNNoise is a suppression-only alternative if WebRTC suppression proves unsuitable; neither denoiser alone replaces AEC. No comparative quality, CPU, memory, battery or end-to-end latency measurements exist from this research.

**Verified integration points in this checkout**

- [Cargo.toml](../Cargo.toml) pins `libwebrtc = "=0.3.54"` **only on macOS/Windows**. [Cargo.lock](../Cargo.lock) resolves `webrtc-sys 0.3.51`, `webrtc-sys-build 0.3.21`, and `cpal 0.18.2`. Iced supplies the UI; these voice packets use CPAL → audiopus → TeamSpeak, not a WebRTC microphone track.
- [AudioEngine][audio] captures normalized `f32`, averages hardware input channels to mono, and resamples to **48 kHz**. `FRAME = 960` is the **20 ms Opus packet**; `BLOCK = 480` is the **10 ms playback block**. `tick()` drains capture first, then encodes, then replenishes playback.
- Immediately after input resampling, `tick()` splits into the local-monitor queue or the Opus PCM queue. Insert microphone processing **before this split** so the local test previews the selected suppression/gain settings. Resampler output counts must be accumulated into exact processing frames; do not assume every call produces exactly 480 samples. [audio.rs][audio].
- Playback combines decoded voice **and received Surface stream audio**, resamples to the selected device, clamps samples, and queues stereo frames. `write_playback()` subsequently ramps app volume, downmixes for mono output, silences unused channels, converts sample format, and emits silence on underflow. Both CPAL callbacks currently discard their timing argument. [audio.rs][audio].
- [client.rs](../src/client.rs) runs voice work on `voice-session`, with a 10 ms tick. It transmits every encoded frame while connected and permitted to capture/send; there is no speech-detection transmission gate. Mute, deafen and server restrictions remain authoritative. The local test opens the audio engine without a server connection.
- [settings.rs](../src/settings.rs) has no processing fields; [main.rs](../src/main.rs) has device, level, volume and local-test controls. [publish_media.rs](../src/streaming/publish_media.rs) separately publishes stereo system audio through `NativeAudioSource::new(AudioSourceOptions::default(), 48000, 2, 50)`. Those defaults disable its three processing flags. Do not route shared music/system audio through the new microphone denoiser/AGC. [Pinned AudioSourceOptions][source-options].

**What the pinned WebRTC API actually permits**

The import is `libwebrtc::native::apm::AudioProcessingModule`. Source permalinks below use the revisions recorded in the installed crates’ `.cargo_vcs_info.json`; the bundled WebRTC header links to the inspected local build artifact. The following was verified in **0.3.54**, its **0.3.51 C++ bridge**, and the locally cached **`webrtc-a545de4` headers**, rather than inferred from upstream main. [Rust wrapper][apm-rs], [bridge configuration][apm-h], [bridge implementation][apm-cpp], [bundled header][webrtc-header].

| Surface | Verified behavior / constraint |
| --- | --- |
| `new(echo, gain, high_pass, noise)` | Four constructor booleans; returns `Self`, not `Result`. C++ builds the APM, applies configuration and calls `Initialize()` without checking its return value. |
| Gain switch | Enables `gain_controller2.enabled` and `gain_controller2.adaptive_digital.enabled`; this is digital AGC, not an OS microphone-volume control. |
| Noise switch | Enables suppression; the bundled configuration defaults to `kModerate`. No suppression-strength setter is exposed by this Rust wrapper. |
| `process_stream(&mut [i16], rate: i32, channels: i32)` | Mutates capture PCM in place. Requires a nonempty multiple of `(rate / 100) × channels` samples, then processes successive 10 ms chunks. At 48 kHz mono that is 480 samples per chunk. |
| `process_reverse_stream(&mut [i16], rate, channels)` | Same framing and mutation contract for the render/reference stream. At 48 kHz stereo that is 960 interleaved samples per 10 ms. Use a separate reference buffer. |
| Integer-format constraints | Bundled header restricts integer processing to 8/16/32/48 kHz, matching capture/output/reverse rates and matching input/output stream layouts. Keep both directions at 48 kHz; resample hardware rates such as 44.1 kHz. Integer PCM is interleaved; the upstream planar-float API is not exposed here. |
| `set_stream_delay_ms(i32)` | Exposed and returns `Result<(), RtcError>`; the documented AEC contract requires supplying stream delay when echo processing is enabled. A fixed guessed delay is not a validated solution. |
| Reconfiguration/reset | No `ApplyConfig`, `Initialize`, reset, statistics, VAD result, float processing or output-muted setter is exposed. Recreate the processor to change switches/reset state, away from the CPAL callbacks. |

Invalid frame lengths **panic** at the Rust assertion; invalid rate/channel values can also cause arithmetic/assertion failure before C++. Validate fixed parameters and framing before calling. Every nonzero native return becomes a generic `RtcErrorType::Internal`; native error codes are discarded, including the header’s nonfatal stream-parameter warning. Processing a multi-frame slice can mutate earlier chunks before a later error: do not assume failure preserves input. Prefer one 10 ms frame per call and retain original input for an explicit fallback policy. [Wrapper][apm-rs], [native errors][webrtc-header].

Proposed sample adapter: sanitize nonfinite floats, clamp to `[-1, 1]`, scale/round/saturate to signed PCM16, then normalize processed PCM back to floats for Opus/monitoring. Define one consistent mapping, including both endpoints (for example scale by 32768 and saturate positive full scale to 32767). **Bypass must retain the original floats**, avoiding unnecessary quantization. These are implementation recommendations, not existing behavior.

**AEC: reference audio, scheduling and lifecycle**

AEC removes speaker audio returning through the microphone; noise suppression targets noise, AGC adjusts level, and room de-reverberation is a different problem. WebRTC’s render/capture contract requires more than enabling a flag. [Bundled APM header][webrtc-header], [Krisp’s distinction between acoustic and room echo](https://help.krisp.ai/hc/en-us/articles/4424862471324-Echo-Cancellation-with-Krisp).

1. Capture a bounded, timestamped copy of the **actual buffer submitted for playback**: voice plus received stream sound, after device-rate conversion, clamping, app-volume ramp, output layout and sample conversion. Account for emitted underflow silence and dropped samples. An earlier `stereo` mix is insufficient; multiplying by the current volume later cannot reconstruct the callback’s ramp. Queue reference data with no allocation, blocking or DSP in the audio callback. [Current render path][audio].
2. On the existing worker, resample/reframe that reference to 48 kHz, preserving the audible channel representation. Keep one processor per audio session and feed render history in order **before processing capture that contains its echo**. Drain available render-reference events before eligible capture frames; merely moving the playback-fill loop above capture is insufficient because queued audio may not play. Bound any alignment wait and detect missing history. [APM ordering contract][webrtc-header]; scheduling is proposed.
3. The documented delay is `(t_render − t_analyze) + (t_process − t_capture)`: hardware playback time minus reverse-processing time, plus capture-processing time minus hardware capture time. Track queueing and resampler delays, sample offsets within callbacks and clock drift. Do not double-count the whole playback queue when the reference was tapped after that queue. [Bundled delay contract][webrtc-header].
4. CPAL exposes input `capture`/`callback` and output predicted `playback`/`callback` timestamps. Its pinned documentation explicitly warns that **different streams need not share a clock origin**. Use within-stream timing plus a validated mapping to the worker’s monotonic time; test CoreAudio/WASAPI behavior. Late reference delivery can make the desired timing invalid and needs resynchronization, not a silent zero-delay assumption. [CPAL 0.18.2 timestamps][cpal-time].
5. Preserve mute/deafen/server gates. On capture disable, clear queued and partially processed microphone frames; never replay pre-mute samples on resume. Proposed initial policy: recreate APM and clear reference/framing state on resume, reconnect, device/rate/layout change, or a detected discontinuity; allow AEC to reconverge. Deafen clears playback and disables capture; volume 0 still drains playback and supplies silence. APM’s muted-output hint is unavailable through this binding. [Existing lifecycle][audio], [client gates](../src/client.rs), [wrapper][apm-rs].
6. Run the local mic test with the same NS/AGC path and raw/processed comparison, using headphones as the UI already requests. Initially bypass AEC there and label the limitation: listening to one’s own mic through speakers creates feedback and is not a reliable AEC test. Validate AEC separately using independent far-end playback and near-end speech. [Current local test](../src/main.rs).
7. Define failures explicitly. Proposed NS/AGC failure policy: bypass using retained original PCM, with a visible warning. Proposed AEC/reference failure policy while AEC was selected: stop microphone transmission and report the failure until the user disables AEC or restarts; silently leaking speaker echo is undesirable. Both policies must always preserve mute/deafen restrictions. Never fail open from a Krisp license/model failure without showing that processing is unavailable.

A reference of Flexspeak’s own output does not include audio played independently by other applications. OS/system loopback would be a separate capture and permission decision, and is outside the minimal AEC plan. The app volume/reference scheme also cannot by itself prove behavior under downstream OS volume, hardware processing, Bluetooth delay or speaker distortion; these require measurements.

**Krisp: two distinct ways to use it**

**Embedded RTC SDK (feasible, conditional).** Krisp documents a native C++ desktop SDK and desktop Windows x86_64/ARM, macOS x86_64/ARM, and Linux x86_64/ARM support. This is the relevant human-call product; Rust bindings advertised for the server-oriented VIVA SDK do not establish a supported RTC Rust crate. [Desktop SDK](https://sdk-docs.krisp.ai/docs/desktop-sdk-bvc), [platform matrix](https://sdk-docs.krisp.ai/docs/supported-platforms), [SDK product distinction](https://sdk-docs.krisp.ai/docs/sdk-or-api).

- Proposed integration: a small C++/C ABI or `cxx` bridge around RTC initialization, session ownership, frame processing and destruction, called at the same microphone seam. The public v9 `Nc<T>` API supports `int16` and `float`, uses caller-owned buffers, and may throw C++ exceptions; translate failures at the boundary and keep allocation/model loading off callbacks. It is not an Iced/JavaScript integration. [Official v9 API](https://cdn.krisp.ai/sdk/doc_v9/class_krisp_1_1_audio_sdk_1_1_nc.html).
- Ship the licensed native libraries plus the appropriate model assets (`.kef` in the documented example); initialize the model/session once for its rate/frame duration and destroy sessions before global teardown. **48 kHz / 10 ms** is a documented desktop combination to evaluate. The overview lists additional frame durations, but its linked v9 enum lists only 10 ms: pin the delivered SDK and trust its headers, rather than promising every overview mode. Float amplitude conventions and ABI/toolchain details still need checking against that delivered package. [Lifecycle/example](https://sdk-docs.krisp.ai/docs/desktop-sdk-bvc), [v9 enums](https://cdn.krisp.ai/sdk/doc_v9/namespace_krisp_1_1_audio_sdk.html).
- The SDK processes audio customer-side; Krisp says network access is for license verification. Thus local audio processing is documented, but **fully disconnected operation, activation, expiry and grace-period behavior are not established here**. Confirm those before promising offline use. The cloud API is a different product and is unnecessary for this proposal. [Security](https://sdk-docs.krisp.ai/docs/security).
- A commercial SDK license is required. Public docs reviewed here do not establish Flexspeak’s price, redistribution/model rights, evaluation entitlement, supported minimum OS/CPU versions or contractual offline terms. Confirm these with the vendor before implementation; app-subscription prices are not embedded-SDK prices. Public documentation was accessible; no licensed binary/model package or private portal was accessed, and nobody was contacted. [SDK licensing](https://sdk-docs.krisp.ai/docs/licensing-information).
- Krisp explicitly places AEC **before NC on capture**, and after any NC on render. Plan WebRTC AEC → Krisp microphone NC, disabling WebRTC NS to avoid stacking denoisers. Do not assume the RTC NC API provides full speaker-reference AEC merely because the Krisp app does. BVC targets other nearby voices and has device-selection restrictions; it should be evaluated separately from ordinary noise suppression. [RTC NC/BVC and AEC placement](https://sdk-docs.krisp.ai/docs/krisp-rtc-bvc-nc), [BVC device requirements](https://sdk-docs.krisp.ai/docs/desktop-sdk-bvc).

**Installed Krisp app (possible workaround, untested here).** On macOS/Windows, install/sign into Krisp, select physical devices there, then select **Krisp Microphone** in Flexspeak; for Krisp-app AEC, also select **Krisp Speaker**. Flexspeak already enumerates selectable CPAL devices, so this is a plausible no-code route, not verified compatibility. Krisp recommends avoiding duplicate app processing. [Official setup](https://help.krisp.ai/hc/en-us/articles/360017441080-Set-up-any-app-with-Krisp), [AEC requires both devices](https://help.krisp.ai/hc/en-us/articles/4424862471324-Echo-Cancellation-with-Krisp), [device enumeration][audio].

The workaround adds a separate app/account/driver dependency. Routing Flexspeak’s combined voice-and-stream output through Krisp Speaker can also expose shared music to its speaker-side processing; evaluate or disable that processing where appropriate. Do not confuse Linux **SDK** support with availability of the same virtual-device desktop-app setup. [Virtual-device behavior](https://help.krisp.ai/hc/en-us/articles/4402174576402-How-Krisp-Microphone-and-Krisp-Speaker-work/).

**RNNoise and platform/build choices**

RNNoise upstream is a C noise-suppression library under **BSD-3-Clause**. Its example uses **48 kHz mono**, and the source defines **480 samples per frame (10 ms)**. Although the API takes `float*`, the official demo copies signed 16-bit PCM values directly into those floats: normalized CPAL floats must therefore be scaled to PCM16 magnitude before processing and scaled back afterward. Query/check `rnnoise_get_frame_size()` for the chosen build. [Upstream README](https://github.com/xiph/rnnoise), [demo/scaling](https://raw.githubusercontent.com/xiph/rnnoise/main/examples/rnnoise_demo.c), [API](https://raw.githubusercontent.com/xiph/rnnoise/main/include/rnnoise.h), [license](https://raw.githubusercontent.com/xiph/rnnoise/main/COPYING).

RNNoise has no render-reference AEC interface or full AGC replacement in that API. It would need a pinned native build/FFI and model provenance; current upstream build preparation downloads model files, so capture those in reproducible packaging. Avoid stacking it with WebRTC NS. If VAD is added later, treat speech-gated transmission as a separate feature; suppression alone must preserve current send behavior. [Upstream API](https://raw.githubusercontent.com/xiph/rnnoise/main/include/rnnoise.h), [build/model instructions](https://github.com/xiph/rnnoise).

**Minimal staged plan — proposed, not implemented**

1. Add saved **Noise suppression: Off / WebRTC** and **Automatic microphone gain: Off / On** settings. Preserve Off for existing/default configurations during initial opt-in evaluation; keep AEC unavailable/off until validated. Keep the high-pass choice internal initially and test it with suppression. Do not expose a strength slider the current binding cannot implement. Use existing settings/client messages, not a provider framework.
2. Add one worker-owned APM plus fixed frame buffers at the post-resample/pre-monitor split. Feed 480-sample frames; continue combining processed samples into existing 960-sample Opus packets. Keep current continuous transmission and source-level microphone meter semantics. Recreate state on settings/lifecycle changes; bypass entirely when all effects are off.
3. Provide local raw/processed listening through the existing headphone test and clear unavailable/error status. Preserve shared system-audio publishing. Validate suppression and optional AGC before considering a default change.
4. Implement timestamped render-reference capture, timeline alignment and explicit reset/failure handling; only then offer AEC experimentally on validated device/platform combinations. Keep one worker as owner; introduce another processing thread only if measured scheduling pressure requires it.
5. If local evaluation identifies a need, compare the same fixtures/devices with licensed Krisp or RNNoise, then choose. Linux support and commercial SDK packaging are separate follow-up decisions; no estimated effort, price or performance guarantee is asserted here.

**Validation required before shipping**

- Framing/conversion: irregular CPAL/resampler chunks, exact 480-sample mono and 960-sample stereo APM frames, 960-sample Opus aggregation, 44.1/48/96 kHz devices, channel order, endpoint saturation, NaN/infinity handling and bypass preserving original samples.
- Signal/state: silence remains finite and bounded; compare clean/soft speech, fan/keyboard noise, nearby voices and gain changes. Test processor recreation, partial-frame reset, overflow/underflow, and deliberate processing errors without stale or partly modified fallback audio.
- Behavior: local test uses NS/AGC without networking; continuous send is unchanged by speech/silence; mute/deafen/server restrictions cannot leak audio; reconnect and device changes reset history; music/system sharing is not denoised or gain-controlled.
- AEC determinism: synthetic delayed/attenuated render echo plus independent near-end speech, changing delay, irregular callback sizes, dropped references, app-volume ramps/0%, mono/stereo layout, clipped mixes and received-stream audio. Check timeline math and error policy separately from subjective quality.
- Hardware validation: macOS and Windows speakers and headphones, built-in/USB/Bluetooth devices, different input/output devices and clock drift, double-talk, volume changes, device loss/recovery and real delay variation. A local microphone loopback test alone cannot establish AEC effectiveness.
- Measure callback underruns, worker CPU, memory, queue depth, startup/model load and end-to-end latency on representative machines, including simultaneous screen publishing/watching. Ten-millisecond frames describe the API cadence, **not** total latency. No such measurements were made for this report.

The actionable next step is opt-in WebRTC microphone suppression and optional digital AGC on macOS/Windows. AEC requires a separate timing/reference milestone; embedded Krisp requires both an evaluation and confirmed commercial terms.
